# hgtv_plain.py 静态审查

审查日期：2026-11-01。对象：用户上传的 `1-hgtv_plain.py`，共 1261 行；以下行号均指该原始文件。本记录只依据源码阅读，未运行脚本、未请求站点、未验证实际视频。

**结论：现有代码不足以支持“红果全集已可播”。** 它能生成页面中可见的集列表和候选播放地址，但没有证明集数完整、内容为整集，或每集实际播放成功。

## 取集与公开播放路径

- `detailContent`（1139–1145）调用 `detail`（415–433），后者调用 `_episodes`（284–329）。取集只请求一次 `/player/<series_id>`（299），合并 JSON-LD 和页面链接（301–323），没有懒加载续取或分页补齐。290 行注释也承认长剧只暴露前若干集。
- 搜索结果的“全 N 集”来自接口字段 `episode_cnt`（410），详情集数则是当前抓到的 `len(eps)`（430）。两者没有比较，缺集不会触发失败；列表标签还可能按抓取顺序重新编号（318–323）。
- 公开地址模板为 `https://hongguoduanju.com/video/public/<vid>/360p.mp4`（42–43）。`playerContent` 在缓存分支之后拼接该地址，预检通过即返回（1179–1183）。地址格式本身不能证明视频为整集，也不能证明这个域名的官方身份。

## 公开试看与完整集不能靠文件头区分

`url_ok`（182–190）仅发送 `Range: bytes=0-15`，判断返回内容非空且前 16 字节含 `ftyp`（185–187）。这只说明响应开头像 MP4；10 秒试看与完整集都可能通过。HTTP 层只向调用方返回响应体（108–117），这里没有验证时长、完整解码、末尾内容、预期集长或集数覆盖。

其他成功出口也没有补足这些证据：缓存直链直接返回（1172–1177）；已有本地文件大于 1024 字节即复用（818–819）；本地服务失败后可重定向到公开地址（929–935）。预检开关还允许完全跳过 `url_ok`（47–48、1181）。因此“返回 URL”“HTTP 可访问”“含 MP4 文件头”均不能等同于“完整集可播”。

确认整集需要另行记录实际时长、与可核实集长的比对、连续解码及结尾结果；确认全集还需要权威集数或完整目录与每集结果对应。本次没有获得这些实测证据，也没有据源码认定公开地址一定是试看。

## 缓存与运行环境依赖

高清路径依赖红果 App 的本地 MMKV 缓存（438–449），并不是从任意剧集 ID 自动获得全集的独立数据源。`hd_cached` 只查本地解析结果（572–576）；无缓存时播放逻辑进入公开地址分支。缓存直链可能包含有时效的 CDN 信息（1171），但返回前没有可用性或时长验证。

文件没有证明外部缓存覆盖了全剧、链接仍在有效期内，或具备适用于第三方播放器的相应授权。这些依赖不能等同于一个可供新安装 App 独立获取任意后续集的通用播放接口。

文件头声明不还原内容密钥、不做解密（18–20），后续却存在手工密钥处理和本地内容处理代码，说明文件说明与实际边界不一致。这部分不能作为完整播放已获验证的依据；本记录不展开其实现或启用方式。

此文件是 Python 程序，含 Python HTTP 服务及外部 FFmpeg 子进程依赖；把 `.py` 文件或 TVBox 配置复制到普通 iOS 播放器，并不能直接运行这些功能。iOS 宿主必须实际支持相应运行时和组件；脚本未提供这种适配或设备验证。`127.0.0.1` 播放地址（555、1167）也只指向播放器所在设备自身，不能自动指向另一台电脑上的服务。
