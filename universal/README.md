# 统一去广告脚本：引擎 + 网站适配器

基于 For-ADM 中搜剧 AI 和 4kvm 两套脚本整理，2026-10-10。

## 结论

可以共用一个脚本、域名白名单、请求路由、输出和失败回退机制；不能仅凭“视频网站”就自动安全地关闭所有广告。当前版本是多个已验证站点适配器的统一入口，不是所有网站自动适用的万能规则。

| 类型 | 已观察到的入口 | 可复用范围 |
| --- | --- | --- |
| 搜剧 AI 配置 | app.experience_snapshot / placements | 使用同一配置协议的站点，需核对字段含义 |
| 搜剧 AI JS | Cp / ti / qu / As / T0 等专用组件与语义标记 | 当前 bundle；混淆变量或编译结构变化需再适配 |
| 4kvm 页面 | ad-item / data-preroll-ad-* | 同一模板与广告属性协议；必须确认不会标记正片 |
| 4kvm JS | prerollAdEnabled + artplayerPluginAds | 使用相同调用代码的站点；仅使用 Artplayer 本身不足以判断 |
| 视频分片广告 | 尚未取得已确认广告分片清单 | 需要针对实际播放清单分析，未实现 |
| 画面内烧录广告 | 广告已是视频画面的一部分 | 本脚本不处理 |

## 使用

使用 quantumult-x-snippet.conf 中的规则。它与原独立规则二选一，避免重复重写同一响应。合并 rewrite_local 和 MITM hostname，保留现有配置与证书。脚本引用仓库 master；客户端如缓存旧脚本，请更新远程重写并清浏览器站点缓存。

## 设计

ad-clean.js 的 adapters 数组选择站点与路径，内部 runSouju / runArtplayer 保留原站点逻辑。只有修改后的正文才返回 body；未注册域名、未匹配路径、未知代码特征、异常响应保持原文。捕获适配器输出后，框架只调用一次 Quantumult X 的 $done。

这是可扩展框架，站点函数名与代码片段依然是适配数据。统一入口便于维护，并不会自动提高原适配器对未知 bundle 的支持。

## 新网站如何接入

1. 获取真实首页、播放页 HTML、JS、广告配置响应；定位广告启用和结束逻辑，记录正片播放入口。
2. 若与现有模板完全相同，将域名加入对应 hosts，并适配 route；若结构不同，新增独立适配函数。仅添加域名不会让不同广告实现自动生效。
3. 为该域名追加精确的 rewrite_local 路径与 MITM hostname；用真实响应检查修改范围、JS 语法、播放地址、选集与弹幕，再在 Quantumult X 实播。

不要全域名匹配所有 JS；不要删除含 ad / ads 的全部函数、请求或字符串；不要屏蔽 Artplayer / HLS 核心文件；不要猜测视频分片广告。
