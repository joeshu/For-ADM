# 启动页与网盘下载倒计时修复（2026-10-21）

当前可可影视为 2.5.16、网飞猫为 2.5.31；共享架构的好好看已到 2.5.24。本次源码全部重新取得，并按原始响应字节归档到 `research/media-resilience/sources/2026-10-21/`。

## 原因

启动页调用广告配置接口后，直接在 `response.data` 中查找 `APP_SPLASH`，没有经过普通广告 getter。上次结构后备虽然可以继续清理普通广告读取，却保留了依赖 webpack 导出别名的配置处理。

下载页是此前明确保留的另一项精确适配：广告初始化、分发、可见状态、倒计时和清理函数位于不同局部函数。升级改变变量、文件和分包位置后，精确指纹不再命中。仅替换数字或放宽变量正则不足以安全处理这一组引用。

## 本次处理

新增受约束的 AST 静态分析，不执行网站函数：

- 根据函数自身的 `/v2/config/units.capi` URL 和 GET 方法绑定，以及实际请求对象的 `url/method/headers/baseURL` 配对，定位广告配置请求函数，将它的返回结果改为已核验的 `{data: []}` Promise。拒绝 URL/方法改写、选项覆盖、未知请求契约及冲突；不依赖数字模块 ID 或 `so` 导出别名。
- 根据下载模块返回的 `data/isAdVisible/countdown/onClickRight/onClickAtMagnet/rightText` 和本地声明，确认三个响应式引用来自同一工厂；再确认广告缓存键、原生计时器清理、初始化与分发函数，以及同一 `.then` 成功回调中的数据赋值和 `setNetdisks`。
- 只有整组绑定完整时，才一次性清理广告数据、将初始倒计时归零，并让初始化/分发函数复位可见状态、倒计时及广告计时器。资源请求、原网盘/磁力数据、错误回调和账户校验保留。

语义阶段设置 2 MiB 大小、600 ms 软时间预算和 500,000 个遍历步数限制。语法不支持、绑定缺失、覆盖/重叠或超预算时，不提交部分语义改写，保留之前精确/结构阶段的结果。

## 验证

使用真实现代/legacy 启动与下载模块进行隔离行为测试，覆盖三个站点：广告配置返回空列表，原启动消费者可正常清空旧广告列表，公告请求函数保持原样；原下载函数在模拟成功响应和旧广告状态下保持倒计时为零、不创建广告计时器/DOM，磁力、网盘及账户数据保持原值。模拟认证失败时，原错误处理保留，未生成可下载资源。

新增人工核验清单登记三站各 248 个当前主脚本/动态分包，审计必须同时核对原始源码 SHA-256 和清理探测计数/结果。源码相同但旧脚本没有清理倒计时，不能判为通过。旧来源清单和旧版规则继续参与回归。

完整仓库回归 773 项全部通过；1,710 份原版脚本均通过输出语法、重复处理稳定性及受保护字段检查，语义改写未发生失败。详细结果见下方验证报告。
