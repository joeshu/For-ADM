# 搜剧AI原生片源接入

搜剧AI通过独立的 `SoujuClient` 接入统一原生页面。它复用 App 的首页、分类、筛选、搜索、详情、分集选择器和 AVPlayer，不把官网装进页面容器，也不要求用户离开 App。

## 原站接口与页面映射

| 原站接口 | App 页面 |
| --- | --- |
| `/v1/runtime/bootstrap` | 服务端当前开放的分类、类型、地区、语言、年份和排序选项 |
| `/v1/feed/home` | 首页栏目及每个栏目的“更多”入口 |
| `/v1/browse/catalog` | 分类、搜索、最新、热播和栏目分页 |
| `/v1/catalog/{id}` | 影片详情、演职员、简介及其他季度 |
| `/v1/catalog/{id}/episodes` | 完整分集；App 仍按每页 20 集显示 |
| `/v1/playback/resolve/{episode-token}` | 当前所选集的可用播放线路 |

站点首页栏目保留原有标题和顺序。分类筛选使用服务端运行配置，不把各栏目的内部筛选值硬编码到页面。栏目“更多”保存经校验的站内查询参数并按服务端游标继续请求。其他季度在详情页单独选择，不加入当前季的备用线路列表。

## 请求、会话和播放

客户端按当前公开网页运行时使用 HMAC-SHA256 请求签名，含请求方法、原始路径、毫秒时间、随机 nonce，并发送站点 Origin/Referer。签名配置来自当前公开前端资源，不是用户凭据。分类只展示运行时接口实际提供的类型；当前线上配置返回电影、电视剧、动漫、综艺和短剧。首次访问只建立原站普通匿名访客会话；只有服务端明确返回会话过期时才续期一次，并沿用同一个匿名访客标识。额度不足、权限拒绝、签名错误和 HTTP 429 不会触发新身份或其他请求重试；429 会进入 30 秒冷却。

访客 Cookie 只存于内存和 iOS Keychain。影片长 ID 通过稳定短 ID 映射以满足 App 既有模型上限；映射保存在本机。分集 token 和签名媒体 URL 只在内存中短暂使用，不写入历史记录、偏好设置或 Keychain。

详情页先读取完整分集，再为第一集请求服务端线路列表。播放时刷新所选集 token，校验响应确属当前集，仅向 App 播放器提供服务端返回的 HTTPS 直连线路；会过滤需要解析器、未解析、会员等级受限和非 HTTPS 的线路。自动线路保留当前集对应的多条直连地址，手动线路不会静默改成另一条。正常访客页面不会自动调用可能消耗额度的 `/v1/playback/resolve-line` 解析接口。

## 真实接口复测

2026-11-02 使用 App 内 `createSourceClient` 和实际运行时签名配置，经常规匿名访客流程复测：

- 首页返回 11 个栏目、共 88 张卡片；栏目“更多”返回 20 条并带后续页。
- 电影分类返回 20 条并可继续分页；“流浪地球”搜索返回 11 项。
- “流浪地球2”详情返回 1 个完整媒体条目、26 条访客直连线路。
- “嫁金钗”电视剧详情返回完整 51 集，第一集有 25 条访客直连线路。
- 通过适配器刷新当前集并解析出播放地址；对第一条地址执行范围读取，收到 HTTP 200/206、`application/vnd.apple.mpegurl`，并确认响应以 `#EXTM3U` 开始。

这项网络检查验证了接口、会话签名和播放清单可达性；它不代替目标 iPhone 上 AVPlayer 的实际解码、设备兼容性和持续播放验收。线路可用性受原站、CDN、地区、网络和防盗链策略影响。

## 维护位置

- `Web/souju-api.mjs`：签名、访客会话、运行时分类、影片分页、完整分集和线路映射。
- `Web/sites.json` 与 `Web/sites-data.mjs`：站点主机、协议版本、公开签名配置和资源指纹。
- `Sources/main.m`：只允许搜剧AI访客 Cookie 进入原生 Keychain 的会话存储范围。
- `tests/souju-api.test.mjs` 和 `tools/website-ui-check.mjs`：离线协议与应用界面回归。

原站改动后先检查公开前端 API 调用和字段，再更新 `souju-api.mjs` 与 `sourceSha256`，同时保留原始字段夹具与离线回归。若接口签名、匿名会话或播放响应变更，应明确报错，不要把访客身份伪装成付费账号，也不要自动尝试额度型解析接口。
